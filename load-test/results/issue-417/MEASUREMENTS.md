# #417 운영 로그 레벨 정리 전후 측정

작성일: 2026-11-06. 원본은 [before.json](before.json), [after.json](after.json), 실행 코드는 `LoggingVolumeExperimentTest`.

## 배경

2026-08-19 운영에서 만료 JWT 요청으로 앱이 순간적으로 초당 약 500줄을 출력했고, 수집기의 컨테이너별 초당 200줄 제한을 넘어 로그 드롭 경보가 반복됐다. 전체 로그 호출 67곳을 조사하니 스택트레이스 외에 토큰·이메일 원문 기록과 레벨 기준 부재가 함께 있었다.

## 측정 방법

- 실제 Tomcat(`RANDOM_PORT`)에 HTTP 요청을 보내고, 루트 로거의 `ListAppender`로 모든 로그 이벤트를 수집한다.
- 레벨은 로컬 `application-prod.yml`과 같은 INFO다. Spring Boot 기본 형식에 가까운 패턴으로 줄 수와 바이트를 센다.
- HTTP 시나리오 200회, 로그아웃 200회, 결과 메일 수신자 100명. 순차 실행이고 결과가 결정적이어서 반복하지 않았다.
- 공개 경로는 `/api/clubs/popular`, 보호 경로는 `/api/favorites`. 공개 경로 `/api/clubs/*`는 JWT 필터를 건너뛰므로 두 경로의 기록 위치가 다르다.
- Redis 호출과 메일 발송은 대체했다. DB는 H2다.

재실행:

```powershell
$env:TTOKTTOK_LOG_EXPERIMENT_OUT = 'load-test/results/issue-417/after.json'
.\gradlew.bat cleanTest test --tests '*LoggingVolumeExperimentTest' -x jacocoTestCoverageVerification
```

결과 메일의 값은 수신자 1명당 값이다.

- SMTP 장애의 스택트레이스는 의도적으로 0 → 1이다. 이전에는 메시지만 남아 원인 분석 근거가 부족했고, 이제 배치당 한 번 남긴다.
- 만료 토큰 1건이 114줄이므로, 수집기 제한 초당 200줄은 초당 약 1.75건에서 넘는다. 사고 당시의 초당 500줄은 이 측정 기준으로 초당 약 4.4건에 해당한다. 측정값으로 환산한 추정이며 사고 당시 요청 수를 확인한 것은 아니다.

## 선택

| 상황 | 수정 후 | 이유 |
|---|---|---|
| 만료 토큰 | DEBUG | 클라이언트의 정상 흐름이다. |
| 손상·위조 토큰 | WARN 한 줄, 스택 없음 | 악용 신호이므로 남기되 비용을 고정한다. |
| 예외 메시지 | 예외 타입으로 대체 | JWT 내용은 요청자가 제어하는 값이다. |
| 인증 성공 | DEBUG | 요청 수에 비례하는 INFO를 없앤다. |
| 수신자별 메일 실패 | WARN 한 줄, 마스킹 | 재발송 판단 근거를 남긴다. |
| 메일 배치 실패 | ERROR 한 줄, 스택 포함 | 장애 시 수신자 수만큼 스택이 쌓이지 않게 한다. |

이슈의 처음 완료 기준은 "실패 시 WARN 한 줄, 예외 메시지 유지"였다. 측정과 조사 뒤 만료 토큰은 DEBUG, 예외 메시지는 타입으로 바꾸고 이슈를 갱신했다.

## 회귀 방지

- `SensitiveLoggingRegressionTest` 6건, `LogMaskerTest` 2건. 음성 대조로 수정 전 코드에서 6건 모두 실패함을 확인했다.
- 레벨 기준은 `rules/reference/coding-rules.md`에 명시했다.

## 한계

- 운영 실제 로그량은 측정하지 않았다. 이 값은 로컬 재현 수치다.
- 운영 설정은 GitHub Secret에서 배치되고, 로컬 `application-prod.yml`로 INFO를 확인했다. 두 값이 같은지는 확인하지 않았다.
- 스택 깊이는 필터 구성과 예외 경로에 따라 달라지므로 운영의 줄 수와 정확히 같지 않을 수 있다.
- 지연·처리량·CPU는 측정하지 않았다. 로그 감소의 성능 효과를 주장하지 않는다.
- 메일 배치 ERROR의 스택에는 SMTP 응답 메시지가 포함된다. 실제 SMTP 응답에 수신자 주소가 있으면 그 한 건에는 남을 수 있다.
- 과거 운영 로그에 이미 남은 토큰·이메일은 이 변경으로 지워지지 않는다.
